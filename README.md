# SOFTCARE — сайт-калькулятор химчистки мягкой мебели

Одностраничный адаптивный сайт с интерактивным расчётом стоимости химчистки.
Демонстрационный проект для портфолио: выглядит как готовый коммерческий продукт,
но не содержит реальных контактов, реквизитов и подтверждённых достижений компании.

**Стек:** HTML5 · CSS3 · Vanilla JavaScript · Vite · Netlify (+ Netlify Function) · Google Sheets как каталог.

Никаких фреймворков, баз данных и CMS.

## 2. Запуск локально

```bash
npm install      # установить зависимости (только Vite)
npm run dev      # dev-сервер: http://localhost:5173
npm test         # автотесты расчётов, CSV и Netlify Function
npm run build    # production-сборка в dist/
npm run preview  # предпросмотр собранной версии
```

Локально сайт работает **без Google Таблицы**: если каталог с сервера недоступен,
используется встроенный демонстрационный каталог (это отражено в статусе над калькулятором).

Проверка Netlify Function:

* `npm test` — функция тестируется напрямую (демо-каталог, разбор CSV, ошибки);
* `npx netlify dev` — реальный локальный запуск (требуется установка `netlify-cli`,
  в проект не входит, чтобы не раздувать зависимости).

## 3. Как работает калькулятор

Формула расчёта (функция `src/lib/calculator.js`, покрыта тестами):

```
база   = Σ (цена изделия × количество)
услуги = Σ (цена выбранной услуги × общее количество изделий)
итого  = база + услуги
```

Правила:

* количество на позицию — целое от **0 до 20**, отрицательные и нечисловые
  значения обнуляются/ограничиваются;
* услуги оплачиваются за каждое выбранное изделие и учитываются только при
  выбранной мебели;
* пустой заказ считается корректно (итог 0 ₽, кнопка заказа блокируется);
* отключённые (`Активен = нет`) и удалённые из таблицы позиции исчезают из
  калькулятора, а ранее сделанный выбор по ним сбрасывается;
* цены нигде не дублируются в коде — они приходят только из каталога.

## 4. Подключение Google Таблицы

Архитектура:

```
Google Sheets (лист «Каталог»)
   → публикация листа как CSV
      → Netlify Function читает CSV по переменной окружения
         → JSON в браузер
            → калькулятор
```

OAuth и API-ключи не нужны: CSV публикуется открыто, читает его серверная функция.

### 4.1. Создание таблицы

1. Создайте таблицу Google (например, `SOFTCARE — каталог`).
2. Переименуйте первый лист в **`Каталог`**.
3. В первую строку вставьте заголовки колонок (можно скопировать из
   `catalog-template.csv`):

   | ID | Тип | Название | Цена | Изображение | Активен |
   |---|---|---|---|---|---|

4. Заполните строки. Пример:

   | ID | Тип | Название | Цена | Изображение | Активен |
   |---|---|---|---|---|---|
   | sofa2 | furniture | Двухместный диван | 2500 | /images/item-sofa-two.webp | да |
   | stains | service | Удаление сложных пятен | 500 | | да |

Требования к полям:

* **ID** — латиница, цифры, `-` и `_`; уникален; при смене ID позиция
  считается новой (старый выбор у посетителя сбросится);
* **Тип** — `furniture` (мебель) или `service` (доп. услуга); допускаются
  варианты «мебель»/«услуга»;
* **Цена** — число, допускаются пробелы и запятая (`2500`, `2 500`, `2500,5`);
* **Изображение** — публичная **https**-ссылка или локальный путь `/images/...`;
  пусто — карточка покажет аккуратную заглушку; `http://`, `javascript:` и
  прочие небезопасные ссылки отбрасываются;
* **Активен** — `да`/`нет` (или `true`/`false`, `1`/`0`). `нет` убирает позицию
  с сайта, но не удаляет строку.

### 4.2. Публикация листа в CSV

1. В Google Таблице: **Файл → Опубликовать в интернете**.
2. На вкладке **«Опубликовать в интернете»** выберите нужный лист (`Каталог`).
3. В выпадающем списке формата выберите **CSV (разделитель — запятая)**.
4. Нажмите **«Опубликовать»** и скопируйте ссылку (вида
   `https://docs.google.com/.../pub?output=csv`).

> Формат «Веб-страница (HTML)» не подойдёт — нужен именно CSV.

### 4.3. Указание ссылки в проекте

Ссылка хранится **только** в переменной окружения Netlify (в код не попадает):

1. Netlify → ваш сайт → **Site configuration → Environment variables**.
2. Добавьте переменную:

   ```
   CATALOG_CSV_URL = https://docs.google.com/.../pub?output=csv
   ```

3. Перезапустите сборку (**Deploys → Trigger deploy → Clear cache and deploy site**).

Локально для запуска функции можно создать файл `.env` (он в `.gitignore`):

```
CATALOG_CSV_URL=https://docs.google.com/.../pub?output=csv
```

### 4.4. Проверка обновлений

1. Откройте `https://<ваш-домен>/api/catalog` — должен вернуться JSON
   с `"source": "google-sheets"` и массивом `items`.
2. Измените цену в таблице → сохраните → подождите несколько секунд (публикация
   CSV обновляется с задержкой) → дождитесь истечения кеша (см. ниже) →
   обновите страницу.
3. Статус над калькулятором должен показать новое время обновления.

### 4.5. Кеширование и частота обновлений

* Netlify Function отдаёт каталог с `s-maxage=300` — **CDN кеширует ответ примерно
  на 5 минут**;
* браузер дополнительно хранит ответ ~60 секунд;
* открытая страница **сама обновляет каталог раз в 5 минут** (и при возврате на
  вкладку), посетителю нажимать ничего не нужно;
* при обновлении выбранные позиции и количество сохраняются, если позиции
  всё ещё есть в каталоге.

Синхронизация **не мгновенная**: правка в таблице может появиться на сайте
в течение нескольких минут (задержка публикации CSV + кеш CDN).

### 4.6. Резервные сценарии

Порядок при недоступности таблицы:

1. каталог из Google Таблицы;
2. последний корректный каталог, сохранённый в браузере (`localStorage`);
3. встроенный демонстрационный каталог (`src/data/demo-catalog.js`).

Статус над калькулятором всегда честно сообщает о ситуации:

* «Каталог обновлён в HH:MM — цены из таблицы» — только когда данные получены
  только что;
* «Свежие цены получить не удалось — показаны сохранённые данные»;
* «Демонстрационный каталог — Google Таблица ещё не подключена».

Сообщение «цены актуальны» при ошибке не показывается.

### 4.7. Резервная копия в Excel

В Google Таблице: **Файл → Скачать → Microsoft Excel (.xlsx)**.

### 4.8. Важно про безопасность

* опубликованный CSV доступен **всем, кто знает ссылку** — не храните в таблице
  персональные данные, комментарии клиентов и другой секретный контент;
* данные из таблицы не вставляются в разметку как HTML: имена и цены
  подставляются через `textContent`, ссылки на изображения проверяются;
* в Netlify Function нет файлового состояния между запусками — каждый вызов
  читает CSV заново, поэтому «пропажа» памяти функции ничего не ломает.

## 5. Форма заявки (текущее состояние)

Форма размечена и готова к подключению:

* поля: имя, телефон, комментарий, согласие на обработку персональных данных;
* расчёт из калькулятора автоматически подставляется в скрытое поле
  `calculation` и блок «Ваш заказ»;
* есть проверка полей с сообщениями об ошибках;
* есть honeypot-поле `bot-field` против спама;
* разметка атрибутов Netlify Forms (`name="order"`, `data-netlify="true"`,
  `form-name`) уже проставлена.

**Отправка намеренно не реализована** — кнопка заблокирована и помечена
сообщением о подключении на следующем этапе. Фиктивной отправки нет:
нажатие не имитирует успех.

Что будет на следующем этапе: подключить Netlify Forms, включить кнопку,
настроить уведомления на почту и страницу благодарности.

## 6. Тесты и проверки

```bash
npm test        # 50 автотестов
npm run build   # production-сборка
```

Что покрыто тестами:

* расчёт: база, услуги × количество, пустой заказ, ограничения 0–20,
  отрицательные значения, отключённые позиции, очистка выбора;
* CSV: кавычки, запятые внутри значений, CRLF, BOM;
* каталог: ошибки строк (дубликат ID, неизвестный тип, некорректная цена,
  небезопасная ссылка), фильтр «Активен», динамическое добавление позиций;
* Netlify Function: демо без переменной окружения, разбор CSV, 502 при
  недоступном CSV, запрет POST, запрет не-https URL;
* форма: валидация имени, телефона, комментария.

Дополнительно проверялось в реальном браузере (Chrome, headless):

* отрисовка каталога, все сценарии расчёта (2 500 → 8 300 ₽), ограничения
  ввода, блокировка кнопки «−» на нуле;
* синхронизация панели расчёта, блока заказа и скрытого поля формы;
* отсутствие горизонтального скролла на 320 / 390 / 768 / 1024 / 1440 px;
* мобильное меню, alt у изображений, подписи полей, единственный `h1`,
  видимый фокус, отсутствие ошибок JS в консоли.
